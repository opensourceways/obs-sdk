# 可观测洞察（概要版）

> 调研时间：2026-10-26。完整调研与来源见 [可观测洞察.md](可观测洞察.md)。
> 本文只保留两张视图：**看技术**（趋势速览）与**看厂商**（国内外主流厂商的路线与前沿实践）。

## 第一章 看技术

| 趋势 | 具体表现 | 代表技术 / 项目 | 成熟度 |
| --- | --- | --- | --- |
| **开放标准统一** | OpenTelemetry 2026-05 从 CNCF 毕业，traces / logs / metrics 全 GA，Profiling 成为第四信号；语义约定（`service.*`、`http.*`、`exception.*`、`cicd.*`）成为跨厂商字段契约 | OTel SDK / Collector / OBI、semconv v1.44.0 | 已标准 |
| **零侵入采集** | 不改代码，靠 eBPF 抓网络与 TLS 明文，自动产出指标、链路，乃至 LLM 调用 span | Grafana Beyla → OBI、DeepFlow、groundcover、Pixie、Tetragon | 生产可用 |
| **Agentic Ops** | 从"告警→人查"变为"检测→假设→验证→处置"；靠拓扑、变更、历史事件做 ground truth，靠审批与审计做 guardrail | Datadog Bits、Dynatrace Intelligence、阿里 STAROps、腾讯 Multi-Agent、Resolve.ai / Traversal / Cleric | 调查可用，修复受控 |
| **AI Agent 可观测** | 观测对象从服务变成 agent：Token 用量、每任务成本、工具调用链、会话回放、效果评估 | `gen_ai.*` 语义约定、Datadog Agent Console、腾讯 Agent 可观测、博睿 AI 可观测 | 快速演进 |
| **遥测成本治理** | 自适应聚合与采样、尾部采样、遥测管道、分层存储；计价从 per-host 转向按量 | Grafana Adaptive Telemetry、Cribl、Datadog Infinite Cardinality | 已成选型首因 |
| **统一数据底座** | 指标 / 日志 / 链路 / 变更进同一套存储与查询；存算分离，按列式或对象存储承载高基数 | Dynatrace Grail、阿里 UModel、博睿 Titan、观测云 GuanceDB 3.0、Observe | 头部已落地 |
| **变更即一级数据** | 把发布、配置、镜像、K8s 事件纳入观测，与故障做叠加分析和风险评分 | 观测云 Change Observability、各家 AI 诊断的变更关联 | 早期 |
| **观测数据 MCP 化** | 厂商把查询、告警、诊断能力暴露为 MCP Server / Skill，供 AI 助手与 IDE 直接调用 | Datadog / Dynatrace / New Relic / Grafana MCP、腾讯 200+ 云产品 MCP、阿里 STAROps Skills | 快速铺开 |

**一句话小结**：采集层已被 OTel + eBPF 商品化，竞争整体上移到**数据底座、成本治理、以及 AI 驱动的分析与处置**；`gen_ai.*` 正在成为继 HTTP 之后的第二套核心语义。

## 第二章 看厂商

### 2.1 国外主流厂商

| 厂商 | 技术路线 | 2026 前沿实践 |
| --- | --- | --- |
| **Datadog** | 全栈平台 + AI 编排（自建后端，per-host 起家转向按量计价） | DASH 2026 发布 100+ 能力：Bits 系列（SRE / Investigation / Code / Release / Agent Builder / Agent Evals）、AI Guard、Agent Console（看编码 agent 用量与花费）、Infinite Cardinality 计价、BYOC 日志 |
| **Dynatrace** | 确定性因果 AI + 实时拓扑（OneAgent + Grail 数据湖） | Perform 2026 推出 Dynatrace Intelligence（Davis 确定性引擎 + agentic AI 融合）；Smartscape 作为 agent 的事实基础；AI Observability app 覆盖 Bedrock AgentCore / LangChain / ADK / OpenAI Agents SDK / MCP |
| **Grafana Labs** | 开源 / OTel-native，LGTM 全栈 + 成本治理 | Adaptive Telemetry 四信号闭环（Profiles 2026-08 GA）；Pyroscope 2.0 重构；Alloy 支持 OTel Collector YAML 模式与远端 Fleet 管理；Beyla/OBI 并入 OTel |
| **Splunk / Cisco** | SIEM + 可观测的广度平台（2026 MQ 为 Challenger） | AgenticOps（Troubleshooting Agent GA、Triage Agent）；2026-04 收购 Galileo 补 Agent 观测与 guardrail；.conf26 推 Cloud Control、Tokenomics、OTel-native 的 Observability Studio |
| **New Relic** | 全栈平台，用量计费 + 合作伙伴集成 | SRE Agent、无代码 Agentic Platform、iRCA、MCP Server；2026-06 推出 AI Coding Observability |
| **Elastic** | 搜索型后端（Elasticsearch + ES\|QL） | ES\|QL、Agent Builder（GA）、Workflows（规则 + agent 混合编排）、Attack Discovery |
| **IBM** | 混合云 + AIOps（Instana + Concert） | 以合规与混合云为差异点，AIOps 编排作为主叙事 |
| **Chronosphere** | 云原生 / 大规模 K8s 的遥测控制（连续三年 Leader，已被 Palo Alto 收购为 Cortex XCOR） | 高基数治理与成本控制；与 Rootly（AI 事件响应）、Checkly（合成监控）通过 MCP / OTel 打通 |
| **Coralogix** | 全栈 + 成本优化（2025 Visionary → 2026 Leader） | 成本优化用例排第 3；覆盖 SRE、IT Ops、DevOps、AI Engineering 等多个用例 |
| **Honeycomb** | 高基数事件分析（Visionary） | 强调 OTel 属性保真；Metrics 于 2026-03 GA；以"可解释的排障"对抗黑盒 AI |
| **groundcover** | eBPF + BYOC，数据不出客户云 | Agent Mode 观测 AI agent 自身；推出 Amazon EKS 原生可观测平台 |
| **Cribl / Observe** | 不做后端：遥测管道 / 对象存储数据湖 | Cribl 专攻路由、脱敏、降本（ARR 超 $200M）；Observe 以 S3 上的"无索引"湖降低存储成本 |
| **AI SRE 新贵** | 只做"定位与处置"，不碰采集 | Resolve.ai（创始团队含 OTel 共同作者，目标 80% 自主处置）、Traversal（因果 ML、默认只读）、Cleric（只读 + 受控写、按次计费） |
| **LLM 观测** | 开发期 trace + 评估 + prompt 管理 | Langfuse、LangSmith、Arize（Phoenix / AX）、Braintrust；OpenLLMetry（Traceloop）已被 ServiceNow 收编；共识是评估与观测共用一个 trace store |

| 厂商 | 技术路线 | 2026 前沿实践 |
| --- | --- | --- |
| **阿里云** | 云厂商一体化：CMS + SLS + ARMS 合并为云监控 2.0，以 UModel 统一数据模型为底座 | STAROps 全域智能运维（智能助手 / 长期任务 / 数字员工，可自建 SRE Agent，OpenAPI + MCP 接入）；ARMS 的 LLM 监控改名 **AI Agent 可观测**（2026-07-30）；已产品化 OTel OBI 接入；Gartner 2026 挑战者（亚太唯一） |
| **腾讯云** | 全栈平台 TCOP + Multi-Agent 架构 | 可观测 AI 工作台（指标 / 链路 / 诊断 Agent 协同），探索与规划双模式；SRE Agent 与 L4 无人值守分级；2026-09 上线 **Agent 可观测**（全链路、Token 成本、效果评估）；200+ 云产品 MCP、tcop-api Skill |
| **华为云** | 一站式 AOM：整合 APM / LTS / CES / Prometheus | AOM 2.0 以应用为中心（CMDB + 容器视角 + 自动化运维），主打"1 分钟发现 / 5 分钟定位 / 10 分钟修复"；2026 年公开新能力少于阿里、腾讯，更多与伙伴联合交付 |

| **博睿数据** | 一体化 APMO + 信创适配（Bonree ONE） | ONE 4.0（2026-05）：AI 可观测栈（模型调用链、Token 成本、对话质量）+ Sage AI 运维智能体工作台 + 统一读写引擎 Titan；IDC 2026H1 APMO 份额 22.1% 居首 |

| **云智慧** | 一体化智能运维（DOCP）+ AIOps | 以业务视角的一体化监控与 AIOps 为主，2026 年公开的新能力细节较少 |

| **开源** | 零侵入与 Prometheus 生态的自建路线 | DeepFlow（eBPF 零侵入，AutoMetrics / AutoTracing / AutoTagging）、夜莺 Nightingale（Prometheus 上层告警与值班）、OpenObserve（Rust + S3 低成本日志） |
