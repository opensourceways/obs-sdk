# 可观测接入指导

面向**基础设施各类业务**的接入指引：自研微服务、面向用户的开源软件、CI 资源与 CI workflow，都能在本文找到自己的路线。

---

## 1. 先选路线：你属于哪一类

| 路线 | 典型对象 | 判定方法 | 核心手段 |
| --- | --- | --- | --- |
| **自研微服务接入** | CLA、评审机器人、账号、CVE 管理等自研服务 | 代码是我们写的，用的是 Go / Python / Node / Java 之一 | 直接用 obs-sdk 四个语言包 |
| **开源软件接入** | Discourse、Etherpad 等**面向用户**的开源软件 | 代码不是我们的，但有独立的用户入口 | 官方 exporter + 黑盒拨测，不改代码 |
| **CI 资源** | runner / 执行机、squid、buildkit、karmada 等 CI 底座 | 关注资源容量与可用性，不关心某条流水线跑什么 | 资源层指标（节点 / 容器 / 队列），复用平台采集 |
| **CI workflow** | GitHub Actions / Jenkins / CodeArts 上的流水线与作业 | 有生命周期与成功/失败语义，但没有常驻 HTTP 服务 | 作业级指标（Pushgateway）+ 事件日志 |

> 一条 CI workflow 跑在 CI 资源上：资源侧指标由平台统一采集，作业侧指标由流水线自己上报。按**观测对象**拆，不按仓库拆。

## 2. 自研微服务接入

代码由我们维护的服务——CLA 的 `app-cla-server`、评审机器人 `review`、账号 `om-webserver`、CVE 管理的 `cve-manager-ng` 等——都走这条路，不论用 Go / Python / Node / Java 哪种语言：直接引对应语言包，**不要自己拼日志库或指标库**。

指标与日志可以分开接，互不依赖。

### 2.1 指标接入

#### 2.1.1 配置环境变量

SDK 把四个部署级字段附加到每条时间序列：

| 字段 | 环境变量 | 缺省值 |
| --- | --- | --- |
| `service` | `OBS_SERVICE` | `unknown` |
| `env` | `OBS_ENV` | `unknown` |
| `instance` | `OBS_INSTANCE` | hostname（k8s 下即 pod 名） |
| `community` | `OBS_COMMUNITY` | `unknown` |

取值优先级：**显式参数 > `OBS_*` 环境变量 > 缺省值**。四语言 SDK 读同一套变量名，部署模板不因语言而异。

> ⚠️ **四个字段恒非空，部署模板里别留空值。** 空值不会输出成 `unknown`，而是让该 label 整段消失——按 `service` 过滤的查询直接查不到这条 series，且不报错。

以评审机器人为例，在 `opensourceways/helm-chart-value` 的 values 里加：

```yaml
# 文件：openeuler/robot/test/values.yaml
deployments:
  - name: robot-universal-review
    env:
      # 可观测静态字段，见 obs-sdk spec/common-fields.md
      - name: OBS_SERVICE
        value: robot-universal-review
      - name: OBS_ENV
        value: test
      - name: OBS_COMMUNITY
        value: openeuler
```

参考 PR：[Open-Infra-Ops/helm-chart-value#1501](https://github.com/Open-Infra-Ops/helm-chart-value/pull/1501/changes)——给 `robot-universal-welcome` 的 Ascend / CANN prod 部署注入 `OBS_*`。

#### 2.1.2 上报代码

**（1）初始化注册表（进程启动一次）**

**Go**

```go
m := obsmetrics.New(obsmetrics.Config{}) // 也可显式传 Service / Env / Instance / Community
```

**Python**

```python
from obs_sdk import metrics
metrics.init()   # 或 metrics.init(service="review", community="openEuler")
```

**Node**

```js
const obs = require('obs-sdk-node');
const m = new obs.metrics.Metrics({ service: 'review' });   // 其余取自 OBS_*
```

**Java**

```java
ObsSdkConfig cfg = ObsSdkConfig.fromEnvironment();   // OBS_* 未设置时回退 unknown / hostname
ObsMetrics m = ObsMetrics.of(cfg);
```

**（2）注册指标（进程启动一次）**

- **名称**：`<service>_<name>_<unit>`，全小写 `snake_case`。
  **注册时传基础名，不带 `_total` / `_seconds`**——Go / Python / Java 的底层库自动补后缀；
  **Node 例外**：prom-client 要最终名，SDK 不改名，得自己写 `pr_handled_total`。
- **类型**：动作计数用 Counter（必须带 `result` 维度）、积压/余量用 Gauge、延迟用 Histogram。
- **label 只放低基数枚举**（`result` / `action` / `kind`）。**禁止** `request_id` / `trace_id` / `span_id` / PR number / commit sha —— 每个不同取值都是一条新时间序列，直接撑爆基数。
- 通用 label（`service` / `env` / `instance` / `community`）由 SDK 自动附加，**不要手写**。

**Go**

```go
handled := m.NewCounterVec("pr_handled", "处理的 PR 事件数", "action", "result")
```

**Python**

```python
handled = metrics.counter("pr_handled", "处理的 PR 事件数", ["action", "result"])
```

**Node**

```js
const handled = m.counter('pr_handled_total', '处理的 PR 事件数', ['action', 'result']);
```

**Java**

```java
ObsMetrics.CounterVec handled = m.counter("pr_handled", "处理的 PR 事件数", "action", "result");
```

**（3）上报（事件发生时）**

业务动作每发生一次就上报一次，成功与失败分别落 `result`；Gauge 用 `set`、Histogram 用 `observe`。

**Go**

```go
handled.Inc("opened", "ok")        // 失败时：handled.Inc("opened", "failed")
```

**Python**

```python
handled.inc(1, action="opened", result="ok")
```

**Node**

```js
handled.inc(1, { action: 'opened', result: 'ok' });
```

**Java**

```java
handled.inc("opened", "ok");
```

**（4）挂中间件、暴露 `/metrics`**

中间件负责三件事：生成/透传 `request_id`、在可信判定点解析 `community`、记录服务端指标
`http_server_requests_total` / `http_server_request_duration_seconds`。
**这两个名字不加任何前缀**——同一条 series 已带 `service` label，四语言共用同一个指标名才能跨服务聚合。

**Go**

```go
// net/http：gin 用 ginmw.Middleware，beego v2 用 InsertFilterChain（用 InsertFilter 会静默漏掉 401/403）
h := obshttpmw.New(obshttpmw.Options{Metrics: m, ResolveCommunity: resolver}).Then(myHandler)
http.Handle("/metrics", m.Handler())
```

**Python**

```python
from fastapi import Response
from obs_sdk.middleware import fastapi_wrap   # Flask: flask_middleware；Django: DjangoMiddleware
fastapi_wrap(app, resolver=resolve_community)

@app.get("/metrics")
def metrics_view():
    return Response(content=metrics.generate_text(), media_type=metrics.content_type())
```

**Node**

```js
const { makeMiddleware, metricsRouteHandler } = obs.middleware;
app.use(makeMiddleware({ metrics: m, resolveCommunity: resolver }));
app.get('/metrics', metricsRouteHandler(m));
```

**Java 不重复埋服务端指标**：把 `m.meterRegistry()` 注册成 bean 交给 Actuator，打开
`management.endpoints.web.exposure.include=prometheus` 即由 Micrometer 官方 instrumentation 产出；
Servlet 侧可选 `ObsFilter`，只用来注入 `request_id` / 解析 `community`。

> 服务侧**不需要配采集**：各集群 Prometheus Agent 用 `kubernetes_sd_configs` 自动发现并直接抓 `/metrics`，
> 不依赖 ServiceMonitor。只需保证端口可达。

**（5）community 请求级覆盖（仅中心化多社区服务需要）**

按社区拆实例的服务，`OBS_COMMUNITY` 一次配好即可。一个实例同时服务多个社区时，必须在**可信判定点**
（路由前缀 / 认证后的主体 / 白名单）解析后写入上下文，**禁止裸读 URL / Header**：

**Go**

```go
ctx = sdkctx.WithCommunity(ctx, "openEuler")
handled.IncWithContext(ctx, "opened", "ok")
```

Python `with _context.bind(community="openEuler"):`；Node `obs.context.bindRequest({ community: 'openEuler' }, fn)`；
Java `try (RequestContext.Scope s = RequestContext.push("openEuler", "req-1", null))`。
未覆盖时自动回退部署默认值。

**（6）自检**

- `curl :<port>/metrics`：业务指标出现，每条 series 的四个通用 label 均非空。
- **零流量时指标不出现是正常的**：指标 vector 懒初始化，没打点就没有 series。别把「查不到指标」当「没接入」。
- **统计请求量时排除自采**：中间件会把 Agent 抓 `/metrics` 的请求也计入，大盘查询带上 `path!="/metrics"`
  （Java 走 Actuator 的对应 `uri!="/actuator/prometheus"`）。
- 中心 Prometheus 能查到该服务的 `http_server_requests_total{service="<name>"}`，才算真正打通采集链路。

### 2.2 日志接入

**（1）初始化部署级字段（同一套 `OBS_*`）**

**Go**

```go
obslog.Init(obslog.Config{Service: "review"})
```

**Python**

```python
from obs_sdk import log
log.init(service="review")          # 进程内幂等
```

**Node**

```js
obs.log.init({ service: 'review' });
```

**Java**

```java
ObsLogging.init(cfg);               // 部署级字段由 ObsJsonProvider 从静态配置输出，恒非空
```

**（2）调用规则：msg 常量 + kv 承载数据**

| 规则 | 说明 |
| --- | --- |
| `msg` 是常量短语 | **禁止 printf**（`"failed for user %s"`）。可变数据一律走 kv，否则每行 `msg` 都不同，LTS 无法按 `msg` 聚合计数，告警规则静默失效 |
| 业务字段平铺 | 键名小写 `snake_case`，优先平铺、不嵌套 |
| 错误走 `error` 字段 | 不要把 err 拼进 `msg`。Go 输出 `err.Error()`；Python 等可含完整 traceback（仍是单行 JSON） |
| `trace_id` / `span_id` 是预留位 | 有值才输出。首期**不要自己生成**，二期 trace 接入后自动可见 |

**Go**

```go
obslog.Info("job done", "event", "release", "issue", "2061")
obslog.ErrorContext(ctx, "get account failed", "user_id", uid, "error", err)  // ctx 里的请求字段自动附加
```

**Python**

```python
logger = log.get_logger(__name__)
logger.info("job done", extra={"event": "release", "issue": "2061"})
```

**Node**

```js
obs.log.info('job done', { event: 'release', issue: '2061' });
```

Java 用 SLF4J，请求级字段来自 MDC；业务字段需在 `logback-json.xml` 的 provider 列表里追加
`<mdc><includeMdcKeyName>tenant_id</includeMdcKeyName></mdc>`，或 SLF4J 2 的结构化 API
`log.atInfo().addKeyValue("tenant_id", id)` + `<keyValuePairs/>`。

**（3）Java 必须用 SDK 提供的样例配置**

把 [java/examples/logback-json.xml](../java/examples/logback-json.xml) 拷成服务的 `logback-spring.xml`。
它只挂 SDK 的 `ObsJsonProvider`，由 SDK 保证字段名、顺序、毫秒 UTC 时间、小写级别与异常堆栈。
**不要退回 encoder 自带 provider**：`<logLevel/>` 只能输出大写、字段名不可配，且不配 `<stackTrace/>`
时 throwable 会被整条丢弃。

**（4）请求上下文**

`request_id` 由入口中间件生成或从可信入站头透传，日志绑定上下文后自动附加；出站调用应继续向下游传播，
保证全链路同一个 ID。`community` 的覆盖规则与指标一致（可信判定点解析，回退部署默认）。

**（5）采集与检索**

- **只写 stdout，一行一个 JSON**：log-agent（fluent-bit，`allContainers: true`）全量采集，服务侧无需配采集。
- 不要写文件，也不要自己加时间戳/级别前缀——格式化全部交给 SDK。
- 不要混入非 JSON 文本行；框架自身的文本日志若无法改造，会以纯文本进入同一日志流，LTS 侧无法按字段检索。
- LTS 中的字段名与契约一致，按 `service` / `community` / `level` / `request_id` 过滤。
  字段能否被检索取决于该日志流是否已配 JSON 结构化——这由平台侧统一配置，接入方不用操作。

**（6）自检**

- 线上抽一行能 `JSON.parse` 成功，`time` 是毫秒 UTC 且以 `Z` 结尾，`level` 小写。
- `service` / `env` / `instance` / `community` 四个字段**都出现且非空**。
- 同一 `request_id` 的多行日志能串起来。
